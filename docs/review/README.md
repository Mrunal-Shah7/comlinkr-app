# Reviews

What is true today, written **before** a change in what the product does, when the plan needs it described first.
One file per review, named `YYYY-MM-DD-short-name.md`, and listed in [../README.md](../README.md).

A review describes current behaviour (with screenshots or quoted messages where they help) and the problems found.
It is followed by a plan in [../plan/](../plan/). For how a whole module behaves, see the system review in
[../system-review/](../system-review/) instead.
